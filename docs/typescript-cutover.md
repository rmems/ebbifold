# TypeScript cutover inventory

Phase 4c retires the inherited TypeScript/Node implementation after the Python
engine, CLI, and local API reached the Phase 4 replacement point. Python is now
the implementation of record.

## Dependency inventory before removal

The active Python engine path had **no runtime or test-time dependency on Node
or TypeScript**:

- no Python module imported or shelled out to Node, `tsx`, npm, or the upstream
  application;
- parity tests read committed JSON fixtures directly;
- corpus tests read `open-content/` directly;
- the CLI and FastAPI app used only Python packages and SQLite.

The remaining TypeScript dependency was **provenance**, not execution: the
golden fixtures had originally been generated by scripts under `python/tools/`
against upstream source under `src/lib/`. Those outputs were already committed
and self-contained, satisfying the removal gate.

## Removed or retired upstream surface

The cutover removes the inactive upstream implementation and its Node-only
tooling rather than keeping a second implementation in the active tree:

- Next.js application and React UI under `src/`;
- upstream server, database, pgvector, Prisma, and migration surface under
  `src/` and `prisma/`;
- Node package manifests and lockfile (`package.json`, `package-lock.json`);
- TypeScript, Next, Vitest, Playwright, ESLint, Vercel, and Prisma config;
- upstream operational scripts under `scripts/` and FOSS export boundary files;
- upstream public web assets under `public/`;
- TypeScript-only CI in `.github/workflows/ci.yml`;
- historical fixture generator scripts under `python/tools/`.

## Preserved contract

The cutover intentionally preserves:

- `open-content/`, including provenance envelopes, media, licences, and the
  frozen validation corpus;
- `schemas/` versioned data contracts;
- all committed golden fixtures under `python/tests/fixtures/`;
- fixture source metadata inside those JSON artifacts;
- `LICENSE`, `LICENSE-CONTENT.md`, and upstream attribution;
- historical design documents as design history, not active operating docs.

## Fixture provenance and regeneration

The last pre-cutover commit containing the TypeScript implementation and
fixture generators is:

```text
fe80cf44766af7f5646061c5b1b533116ce22000
```

The committed fixture JSON files are the canonical oracle. Python tests must
continue to consume those artifacts directly and fail closed if they are
missing or malformed. Regenerating a fixture is a deliberate archaeology task:
check out the pre-cutover commit in a separate worktree, run the historical
generator there, copy only the resulting JSON artifact forward, and explain the
provenance change in the pull request. Do not reintroduce the generator or the
TypeScript implementation into the active tree.

## Active verification boundary

The active verification commands are Python-only:

```bash
cd python
uv sync --group dev
uv run pytest -q
```

CI must remain Python-only for the core engine. If a future lane needs Node for
an isolated experiment, it must be introduced as a separate explicitly optional
workflow and must not become part of the scheduler, corpus, CLI, API, or
fixture-validation path.
